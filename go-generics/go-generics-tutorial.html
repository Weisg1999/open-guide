2. 类型约束初级

2.1 内置与标准库约束

any          // = interface{}，任意类型，但什么操作都做不了（只能赋值传参）
comparable   // 可用 == / != 比较的类型（int/string/指针/struct…，不含 slice/map/func）

cmp.Ordered             // ~int|~int64|~uint|~float32|~float64|~string（可排序可比较）
constraints.Integer     // golang.org/x/exp/constraints：所有整数
constraints.Float       // 所有浮点

2.2 约束即接口：方法约束

Go 泛型最优雅的设计：约束就是接口。约束代表一个「类型集合」，类型实参必须落在集合内。

// T 必须实现 String() 方法
type Stringer interface {
    String() string
}

func Join[T Stringer](items []T) string {
    var sb strings.Builder
    for _, v := range items {
        sb.WriteString(v.String())  // 编译器保证 T 有此方法
    }
    return sb.String()
}

3. 泛型类型与方法初级 → 中级

type Stack[T any] struct {
    items []T
}

// 关键：方法的 receiver 必须带 [T]，不能新增类型参数
func (s *Stack[T]) Push(v T) {
    s.items = append(s.items, v)
}

func (s *Stack[T]) Pop() (T, bool) {
    if len(s.items) == 0 {
        var zero T              // var 声明拿到 T 的零值
        return zero, false
    }
    n := len(s.items) - 1
    v := s.items[n]
    s.items = s.items[:n]
    return v, true
}

// 使用：实例化后就是普通类型
s := &Stack[int]{}
s.Push(1)
v, ok := s.Pop()   // v=1, ok=true

更多泛型类型形态

type Map[K comparable, V any] map[K]V       // map 的 key 必须可比较
type Transformer[T, U any] func(T) U           // 泛型函数类型
type Pair[K comparable, V any] struct {    // 多类型参数
    Key K
    Val V
}
💡 零值技巧：泛型代码里不能写 T{}（T 可能是内置类型）也不能随便用 nil（T 可能是值类型）。标准姿势：var zero T 或 *new(T)。

4. 进阶技巧中级

4.1 指针与值方法集的坑

⚠️ 核心规则：泛型代码中，T 不会自动拥有 *T 的方法，反之亦然。[T Speaker] 传 Cat{} 还是 &Cat{}，取决于方法用的是值接收者还是指针接收者。
type Cat struct{}
func (c Cat) Speak() string  { return "meow" }   // 值接收者：Cat 和 *Cat 都实现
func (c *Cat) Speak2() string { return "meow" } // 指针接收者：只有 *Cat 实现

func MakeSound[T Speaker](t T) string { return t.Speak() }

MakeSound(Cat{})      // ✅ 值方法集满足
MakeSound(&Cat{})     // ✅ 指针方法集包含值方法

4.2 递归约束：让方法返回「自身类型」

type Clonable[T any] interface {
    Clone() T          // 约束引用类型参数自身
}

func CloneAll[T Clonable[T]](xs []T) []T {  // 注意嵌套写法
    out := make([]T, len(xs))
    for i, x := range xs {
        out[i] = x.Clone()
    }
    return out
}

4.3 关联值与指针：interface{ *T }

// PT 约束：既是 *T，又实现 String —— 编译期把「类型」和「它的指针」绑定起来
func Process[T any, PT interface{ *T; String() string }](v PT) {
    fmt.Println(v.String())
}

4.4 泛型 channel 工具与 Option 类型

// FanIn：多 channel 合一
func FanIn[T any](chans ...<-chan T) <-chan T {
    out := make(chan T)
    var wg sync.WaitGroup
    wg.Add(len(chans))
    for _, ch := range chans {
        go func(c <-chan T) { defer wg.Done(); for v := range c { out <- v } }(ch)
    }
    go func() { wg.Wait(); close(out) }()
    return out
}

// 类型安全的可选值（Rust 风味）
type Option[T any] struct { val T; valid bool }
func Some[T any](v T) Option[T] { return Option[T]{v, true } }
func (o Option[T]) UnwrapOr(fallback T) T {
    if o.valid { return o.val }
    return fallback
}

5. 实现原理：GC Shape Stenciling高级

Go 没有采用 C++ 的全量单态化（每个实参生成独立机器码，代码膨胀），也没有采用 Java 式完全擦除（性能损失大），而是混合方案：

接口 vs 泛型 选型

维度接口（运行时多态）泛型（编译期多态）
绑定时机运行时编译期
异构集合 []any 混装✅❌
同构算法（对 []T 统一处理）一般✅ 类型安全 + 性能双优
存储/传递「未知类型」✅❌
算子类需求（T op T）❌ 接口无法表达✅ 约束直接表达

6. 限制与常见坑高级

🚫 方法不能有额外类型参数：提案 #49085 讨论多年仍未放开。变通：写成顶层泛型函数。
func (s Stack[T]) Map[U any](f func(T) U) []U  // ❌ 编译错误

// ✅ 变通方案
func MapStack[T, U any](s Stack[T], f func(T) U) []U { ... }
🚫 泛型类型不能做类型断言 / switch 的 case：只能先转成 any 再断言。
switch v := x.(type) {
case T:              // ❌ T 不是具体类型
}
⚠️ 不要为了泛型而泛型：约束是 any 然后内部各种类型断言的写法，完全违背泛型初衷——那不如直接用 any。泛型的前置条件是算法与类型无关（比较、索引、映射……）。
⚠️ comparable ≠ 可排序：slice/map/func 不满足 comparable；cmp.Ordered 才支持 < >。结构体含不可比较字段（如 slice）时 == 会运行时 panic。
⚠️ 接口零值陷阱：T 实例化为接口类型时 var zero T 是 nil，业务判断需用类型信息而非简单比较。

7. 综合实战：类型安全的 TTL 缓存高级

package cache

import (
    "sync"
    "time"
)

type entry[V any] struct {
    val       V
    expiresAt time.Time
}

// 并发安全、带 TTL、K/V 类型编译期绑定的内存缓存
type Cache[K comparable, V any] struct {
    mu     sync.RWMutex
    data   map[K]entry[V]      // K comparable → 可做 map 键
    ttl    time.Duration
    loader func(K) (V, error)
}

func New[K comparable, V any](ttl time.Duration, loader func(K) (V, error)) *Cache[K, V] {
    return &Cache[K, V]{
        data:   make(map[K]entry[V]),
        ttl:    ttl,
        loader: loader,
    }
}

func (c *Cache[K, V]) Get(k K) (V, bool) {
    c.mu.RLock()
    e, ok := c.data[k]
    c.mu.RUnlock()
    if !ok || time.Now().After(e.expiresAt) {
        var zero V           // 零值技巧处理失败路径
        return zero, false
    }
    return e.val, true
}

func (c *Cache[K, V]) GetOrLoad(k K) (V, error) {
    if v, ok := c.Get(k); ok {
        return v, nil
    }
    v, err := c.loader(k)
    if err != nil {
        var zero V
        return zero, err
    }
    c.Set(k, v)
    return v, nil
}

func (c *Cache[K, V]) Set(k K, v V) {
    c.mu.Lock()
    c.data[k] = entry[V]{v, time.Now().Add(c.ttl)}
    c.mu.Unlock()
}
✅ 泛型化收益：对比 1.18 之前的 map[interface{}]interface{} 版本——调用处零断言、编译期防错、值类型不装箱。要点：K comparable 做 map 键、var zero V 处理失败、receiver 带 [K, V]。
