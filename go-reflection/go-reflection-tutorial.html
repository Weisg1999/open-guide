Go 反射（Reflection）

Go 在运行时「审视类型结构与值」的能力，是 encoding/json、fmt、ORM、依赖注入框架的共同基石。本教程从三定律出发，由浅入深直到手写 mini-json 与性能优化。

1. 什么是反射入门

你一定写过这样的代码，却没意识到背后是反射在工作：

type User struct {
    Name string `json:"name"`
    Age  int    `json:"age"`
}

b, _ := json.Marshal(User{Name: "alice", Age: 20})
// 输出：{"name":"alice","age":20}

json.Marshal 如何知道结构体有哪些字段、tag 写了什么？——答案：运行时用反射解析了这个结构体。

反射解决的根本问题：编译期不知道类型长什么样，运行时才需要知道。典型场景：序列化（json/yaml/protobuf）、ORM 字段映射、依赖注入、fmt.Println 万物皆可打印、框架「约定优于配置」。

1.2 反射的入口：interface 的隐藏结构

2. 反射三定律入门 → 初级

// 定律 1：interface → 反射对象
var x float64 = 3.4
t := reflect.TypeOf(x)   // float64 —— 类型元信息
v := reflect.ValueOf(x)  // 3.4   —— 值的视图
fmt.Println(t.Kind())  // float64
fmt.Println(v.Float())  // 3.4

// 定律 2：反射对象 → interface
y := v.Interface().(float64)   // 类型断言还原
💡 性能第一课：TypeOf/ValueOf 的参数是 interface{}——传进去的那一刻就发生了装箱（值逃逸到堆），这是反射性能成本的第一来源。

2.3 第三定律：可设置性（最经典的坑）

3. reflect.Type：类型的显微镜初级

3.1 Type 与 Kind 的区别（90% 的人会混淆）

type MyInt int
type User struct{ Name string }

reflect.TypeOf(MyInt(1)).Name()  // "MyInt"      ← Type：声明的名字
reflect.TypeOf(MyInt(1)).Kind()  // reflect.Int ← Kind：底层种类

reflect.TypeOf(User{}).Name()    // "User"
reflect.TypeOf(User{}).Kind()    // reflect.Struct

Kind 是一个枚举（Int / String / Slice / Struct / Ptr / Map / Func / Chan / Interface…），反射的分支逻辑几乎总是基于 Kind 而非 Type——因为「按种类处理」才可穷举。

3.3 遍历结构体字段与 Tag

type User struct {
    Name string `json:"name" validate:"required"`
    Age  int    `json:"age" validate:"gte=0,lte=150"`
}

u := User{Name: "alice"}
t := reflect.TypeOf(u)
for i := 0; i < t.NumField(); i++ {
    f := t.Field(i)
    fmt.Printf("字段:%-6s 类型:%-8s json:%-10s validate:%s\n",
        f.Name, f.Type, f.Tag.Get("json"), f.Tag.Get("validate"))
}
// 字段:Name   类型:string  json:name        validate:required
// 字段:Age    类型:int     json:age         validate:gte=0,lte=150

f.Tag.Get(key) 就是 json 库做字段重命名、validator 库做校验的核心机制。另有 Tag.Lookup(key) 可区分「没有 tag」和「tag 为空」；f.Index（[]int）支持嵌套字段寻址。

4. reflect.Value：值的操作台初级 → 中级

读取 / 判空 / 创建

v := reflect.ValueOf(x)
v.Int() / v.Uint() / v.Float() / v.Bool() / v.String()  // 按 Kind 取（返回最大宽度类型）
v.Len()            // slice/map/chan/array/string 长度
v.Index(i)         // slice/array 元素 → Value
v.MapIndex(key)    // map 取值 → Value
v.Field(i)         // 结构体字段 → Value

v.IsValid()   // 零值 Value 为 false（越界/未命中都返回零值 Value）
v.IsNil()      // 仅对 chan/func/interface/map/ptr/slice 有意义
v.IsZero()     // Go 1.13+

// 运行时按类型信息创建新值（json 反序列化的第一步）
t := reflect.TypeOf(User{})
pv := reflect.New(t)              // *User，指向新分配的零值 User
m := reflect.MakeMap(reflect.TypeOf(map[string]int{}))
⚠️ 注意：v.Int() 返回 int64，赋回 int 需要 int(v.Int())——访问器一律返回最大宽度的类型。

5. 动态调用与修改中级

5.1 动态调用函数与方法

func Add(a, b int) int { return a + b }

fv := reflect.ValueOf(Add)
out := fv.Call([]reflect.Value{reflect.ValueOf(1), reflect.ValueOf(2)})
fmt.Println(out[0].Int())   // 3

// 方法调用：方法名必须是导出的
type Greeter struct{ Name string }
func (g *Greeter) Hello(who string) string { return "hi " + who }

g := &Greeter{Name: "alice"}
m := reflect.ValueOf(g).MethodByName("Hello")
out = m.Call([]reflect.Value{reflect.ValueOf("bob")})

5.2 通用 SetField：反射修改的标准骨架

func SetField(obj any, name string, value any) error {
    v := reflect.ValueOf(obj).Elem()      // 传指针 + Elem 得到可设视图
    f := v.FieldByName(name)
    if !f.IsValid() || !f.CanSet() {
        return fmt.Errorf("field %s not settable", name)
    }
    fv := reflect.ValueOf(value)
    if fv.Type().AssignableTo(f.Type()) {  // 类型必须可赋值
        f.Set(fv)
        return nil
    }
    return fmt.Errorf("type mismatch: %s -> %s", fv.Type(), f.Type())
}

c := &Config{}
_ = SetField(c, "Host", "localhost")
_ = SetField(c, "Port", 8080)      // 配置热加载、ORM Update、依赖注入的通用骨架

6. mini-json：反射的集大成实战中级

约 40 行实现 json.Marshal 的核心骨架——按 Kind 递归分派，这是所有序列化库的主干逻辑：

func encodeValue(rv reflect.Value, sb *strings.Builder) error {
    switch rv.Kind() {
    case reflect.Struct:
        t := rv.Type()
        sb.WriteByte('{')
        first := true
        for i := 0; i < t.NumField(); i++ {
            f := t.Field(i)
            if f.Tag.Get("json") == "-" {      // "-" 表示跳过
                continue
            }
            if !first { sb.WriteByte(',') }
            first = false
            name := f.Tag.Get("json")
            if name == "" { name = f.Name }             // 无 tag 用字段名
            fmt.Fprintf(sb, "%q:", name)
            if err := encodeValue(rv.Field(i), sb); err != nil {
                return err
            }
        }
        sb.WriteByte('}')
    case reflect.Slice, reflect.Array:
        sb.WriteByte('[')
        for i := 0; i < rv.Len(); i++ {
            if i > 0 { sb.WriteByte(',') }
            encodeValue(rv.Index(i), sb)
        }
        sb.WriteByte(']')
    case reflect.String:
        fmt.Fprintf(sb, "%q", rv.String())
    case reflect.Int, reflect.Int64:
        fmt.Fprintf(sb, "%d", rv.Int())
    case reflect.Bool:
        fmt.Fprintf(sb, "%v", rv.Bool())
    default:
        return fmt.Errorf("unsupported kind: %s", rv.Kind())
    }
    return nil
}

真实标准库还要处理 map、指针、interface、浮点转义、自定义 Marshaler 接口……但骨架完全一致。读懂这段代码，就读懂了 json.Marshal 的主干。

7. 性能与最佳实践高级

成本来源说明
装箱值 → interface{} 逃逸到堆（TypeOf/ValueOf 的参数就是接口）
间接访问每次读字段/调方法都要经过 Value 结构中转
无法内联动态分发天然阻止编译器优化
运行时检查AssignableTo / CanSet 等校验开销
⚠️ 量级感知：反射字段读取比直接访问慢一个数量级以上（每次几十 ns vs 1~2 ns）。对每秒百万级调用的热路径，这是架构级问题。

四条缓解手段

手段做法使用者
缓存类型信息Type/Field 元信息按类型缓存一次，别每请求重算encoding/json 内部类型缓存池
预生成代码codegen 替代反射easyjson、protobuf 早期方案
泛型替代「对 []T 的操作」用泛型获得编译期绑定，零反射Go 1.18+ 标准库 slices/maps
反射只用在边界框架边界（序列化/注入）用反射，核心热路径用具体类型一切成熟的框架设计

安全清单（panic 三大来源）

🚫 源 1：Kind 不匹配的方法调用——对 int 调 v.String()。先判 Kind 再操作。
🚫 源 2：不可设值的 Set——没传地址。先查 CanSet()。
🚫 源 3：零值 Value 的任何操作——Field 越界 / MapIndex 未命中返回 Value{}。先查 IsValid()。
⚠️ 未导出字段：类型信息可读，但 CanSet() 为 false（除非 unsafe，不推荐）。

8. 反射 vs 泛型：如何选择高级

维度反射泛型
绑定时机运行时编译期
类型安全无（运行时才炸）完整
性能慢（装箱 + 间接）快（静态绑定）
能力上限任意类型结构（字段名、tag、动态调用）只能用约束表达的操作
典型场景序列化、ORM、DI、fmt容器、算法、工具函数
✅ 组合套路：泛型定骨架 + 反射看内部。例如泛型缓存 [K, V] 编译期绑定类型，内部用反射解析 V 的 tag 实现字段映射——两者互补而非替代。
