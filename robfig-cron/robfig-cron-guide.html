robfig/cron

Go 语言事实标准的进程内定时任务调度器：以标准 cron 表达式驱动，单 goroutine 调度 + 每任务独立执行，支持秒级精度、时区、装饰器链与优雅停止。

github.com/robfig/cron 当前主线 v3 Go 1.11+ MIT License

1. 库简介

robfig/cron 把 Unix cron 守护进程的核心能力搬进了 Go 应用：用标准 5 字段 cron 表达式（分 时 日 月 周）描述触发时间，到点自动执行注册的函数或对象。

它解决的是「单进程内的周期性触发」问题——不持久化、不分布式、错过的触发不补跑。在「一个服务里跑几个定时逻辑」的场景下它几乎是无脑之选；若需要分布式、可重试、可观测的任务队列，请考虑 Asynq 等方案。

go get github.com/robfig/cron/v3
import "github.com/robfig/cron/v3"

2. 功能特性总览

⏱️
标准表达式默认解析 5 字段标准 cron spec，首字段为「分」，符合 Wikipedia 规范
⚡
秒级精度cron.New(cron.WithSeconds()) 开启 Quartz 兼容的 6 字段布局（不支持年字段）
📅
预定义描述符@yearly / @monthly / @weekly / @daily / @hourly / @every 5m 开箱即用
🌏
时区支持全局 WithLocation()；单条表达式可用 CRON_TZ=Asia/Tokyo 前缀（兼容旧 TZ=）
🔄
动态管理运行中 Add / Remove / Entries 快照，全部通过 channel 传递，线程安全
🧅
装饰器链Chain + JobWrapper 提供可插拔横切能力：Recover / SkipIfStillRunning / DelayIfStillRunning
📝
结构化日志兼容 go-logr 的 Logger 接口，可对接 zap / logrus 等主流日志库
🛑
优雅停止Stop() 返回 context.Context，可等待所有正在执行的任务结束后再退出

3. 核心概念与架构

五个核心抽象

抽象职责
Cron调度器本体。独占一个调度 goroutine，通过 add / remove / snapshot / stop 四个 channel 与外界通信
Schedule何时执行。接口唯一方法 Next(t) time.Time。内置 SpecSchedule（表达式）与 ConstantDelaySchedule（@every 固定间隔）
Job做什么。接口唯一方法 Run()；FuncJob 是 func() 的现成适配器
Entry一条调度记录：ID + Schedule + Job + Next（下次触发）+ Prev(上次触发)
Chain怎么包着做。JobWrapper 是 func(Job) Job，按传入顺序从外到内包裹任务

4. 运行循环原理

Start() 之后，run() 在一个独立 goroutine 里持续运转。理解这个循环，就理解了 robfig/cron 的一切行为特征。

关键源码（有删减）

// 触发到点任务：每个任务独立 goroutine，互不阻塞
case now = <-timer.C:
    for _, e := range c.entries {
        if e.Next.After(now) || e.Next.IsZero() {
            break
        }
        c.startJob(e.WrappedJob)          // go func(){ j.Run() }()
        e.Prev = e.Next
        e.Next = e.Schedule.Next(now)     // 立即求解下一次触发
    }
✅ 结论：① 单 goroutine 调度 → entries 读写无锁；外部 Add/Remove/Entries 通过 channel 传递，这是线程安全的来源。② 排序 + Timer 精确休眠而非轮询。③ 错过的触发直接跳过（无补跑）。④ 默认允许任务重叠执行。

5. 表达式全解析

预定义描述符

描述符等价表达式含义
@yearly / @annually0 0 1 1 *每年 1 月 1 日 0 点
@monthly0 0 1 * *每月 1 日 0 点
@weekly0 0 * * 0每周日 0 点
@daily / @midnight0 0 * * *每天 0 点
@hourly0 * * * *每小时第 0 分
@every 1h30m—从添加时刻起固定间隔（time.ParseDuration 语法）
⚠️ 注意：@every 1h 是「固定间隔」（从 Add 时刻起算，走 ConstantDelaySchedule），而 0 * * * * 是「整点对齐」（走 SpecSchedule），两者语义不同。另外 Dom 与 Dow 同时指定时是「或」关系：0 0 1 * 1 = 每月 1 号或每周一的零点。

6. 装饰器链（Chain / JobWrapper）

Chain 是 robfig/cron v3 最优雅的设计：JobWrapper 是 func(Job) Job，Chain 按传入顺序从外到内包裹任务，形成洋葱结构，为任务注入横切行为。

内置三个 JobWrapper

Wrapper行为实现要点
Recover(logger)捕获任务 panic 并记录堆栈日志defer recover() + runtime.Stack；v3 默认不 recover，必须显式挂载
SkipIfStillRunning(logger)上一次没跑完则跳过本次触发容量 1 的 channel 非阻塞抢锁，抢不到即 skip
DelayIfStillRunning(logger)上一次没跑完则排队等待（串行化）mutex 互斥，延迟超 1 分钟记 Info 日志

7. 代码实战

7.1 快速上手

package main

import (
    "fmt"
    "time"

    "github.com/robfig/cron/v3"
)

func main() {
    c := cron.New() // 标准 5 字段解析器，时区 time.Local

    // 每分钟打印一次
    c.AddFunc("* * * * *", func() {
        fmt.Println("每分钟触发:", time.Now().Format("15:04:05"))
    })

    // 每天凌晨 2:30（表达式非法时返回 error）
    _, err := c.AddFunc("30 2 * * *", func() {
        fmt.Println("每日对账任务")
    })
    if err != nil {
        panic(err)
    }

    c.Start()
    defer c.Stop()

    select {} // 阻塞主 goroutine
}

7.2 秒级精度与预定义描述符

c := cron.New(cron.WithSeconds()) // 6 字段：秒 分 时 日 月 周

c.AddFunc("*/5 * * * * *", func() {})     // 每 5 秒
c.AddFunc("0 30 9 * * MON-FRI", func() {}) // 工作日 9:30:00

c2 := cron.New()
c2.AddFunc("@every 2h30m", func() {}) // 每 2.5 小时（固定间隔）
c2.AddFunc("@daily", func() {})       // 每天 0 点

7.3 时区处理

// 方式一：全局时区
loc, _ := time.LoadLocation("Asia/Shanghai")
c := cron.New(cron.WithLocation(loc))

// 方式二：单表达式指定时区（规格化写法，推荐）
c.AddFunc("CRON_TZ=Asia/Tokyo 0 6 * * *", func() {}) // 东京时间早 6 点

7.4 自定义 Job（实现 Job 接口）

type SyncJob struct {
    Table string
}

func (s *SyncJob) Run() {
    fmt.Printf("同步表 %s ...\n", s.Table)
}

func main() {
    c := cron.New()
    id, _ := c.AddJob("*/10 * * * *", &SyncJob{Table: "orders"})
    fmt.Println("entry id:", id)
    c.Start()
    select {}
}

7.5 装饰器：panic 恢复与防重叠

c := cron.New(
    cron.WithChain(
        cron.Recover(cron.DefaultLogger),            // 捕获 panic 并记日志
        cron.SkipIfStillRunning(cron.DefaultLogger), // 上次未跑完则跳过本次
    ),
    cron.WithSeconds(),
)

c.AddFunc("*/5 * * * * *", func() {
    panic("boom") // 不会拖垮调度器
})

// 自定义 JobWrapper 也非常简单：
func WithMetric(name string) cron.JobWrapper {
    return func(j cron.Job) cron.Job {
        return cron.FuncJob(func() {
            start := time.Now()
            j.Run()
            recordDuration(name, time.Since(start)) // 上报耗时
        })
    }
}

7.6 运行中动态管理任务

c := cron.New()
c.Start()

id, _ := c.AddFunc("*/1 * * * *", func() { fmt.Println("tick") })
// 运行中添加：经 add channel 交给调度 goroutine，立即生效

for _, e := range c.Entries() { // 快照，线程安全
    fmt.Printf("entry=%d next=%v prev=%v\n", e.ID, e.Next, e.Prev)
}

time.Sleep(5 * time.Minute)
c.Remove(id) // 移除；c.Entry(id) 可查单个条目

7.7 优雅停止与日志

ctx := c.Stop() // 发停止信号，不再派发新触发
<-ctx.Done()    // 等待所有「正在执行」的任务结束（内部 sync.WaitGroup）
fmt.Println("所有任务已退出")

// 集成结构化日志：输出 schedule/wake/run/added/removed 事件，排查「为什么没触发」必备
logger := cron.VerbosePrintfLogger(log.New(os.Stdout, "cron: ", log.LstdFlags))
c := cron.New(cron.WithLogger(logger))
💡 Start vs Run：Start() 起后台 goroutine 立即返回；Run() 在当前 goroutine 阻塞执行，适合「进程只跑调度器」的场景。两者重复调用都是 no-op。

8. 常见坑与最佳实践

🚫 忘记 Start()：Add 之后不 Start，任务静静躺在 entries 里永远不会执行。
🚫 panic 不再默认恢复：v3 默认不 recover。生产环境务必挂 cron.Recover(logger)，否则一个任务的 panic 会崩掉整个进程。
⚠️ v1 → v3 迁移：默认解析从「可选秒字段的 6 段」变为「标准 5 段」。* * * * * 在 v1 是每秒、在 v3 是每分。要秒级请 WithSeconds()。
⚠️ 长任务重叠：默认允许同一任务并发多份。清理 / 上报类任务通常要加 SkipIfStillRunning。
⚠️ 错过即跳过：进程重启后不会补跑停机期间错过的触发，需要补偿逻辑请在任务内部自行实现（如对比 e.Prev）。
⚠️ 时区陷阱：服务器时区 ≠ 业务时区时，显式 WithLocation 或 CRON_TZ=；夏令时切换日建议业务上使用无夏令时时区。
⚠️ K8s 多副本：每个 Pod 各跑一份 cron，同一任务会被触发 N 次。需要分布式锁（Redis SET NX）或改用中心化调度 —— 这是 robfig/cron 与分布式任务队列（Asynq 等）的本质边界。

9. 版本演进

v1
最初版本，gopkg.in 分发；默认「可选秒字段」格式，与标准 cron / Quartz 均不兼容，是混乱之源
v2
分支版本，引入移除任务等能力，未成为默认
v3（2019.6，当前推荐）
Go Modules（github.com/robfig/cron/v3）· 标准 5 字段为默认 · Chain/JobWrapper 装饰器 · go-logr 日志接口 · 函数式选项（WithLocation / WithParser / WithChain / WithSeconds / WithLogger）· 修复「删除任务导致下一任务延迟执行」等多个历史 bug

v3 发布后 API 趋于稳定，社区以维护为主，新项目直接使用 v3 即可。
